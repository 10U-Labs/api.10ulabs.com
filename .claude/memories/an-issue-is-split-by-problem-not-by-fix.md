# Issues divide, batches merge

The work is divided by issues, each documenting one indivisible problem, and merged by batches, which take every open issue of one stack into one working session. So an issue is split as finely as its problems run, and never merged with another because they share a fix, a module or a batch: the batch already brings them together. A misnamed value threaded through one module is one problem; the same misnaming in another module, or in a served value, a report key or a log line, is another.

**Why:** On 2026-10-05 a session asked whether to file one issue per module or one per group to keep the count down, then folded #149, #150, #151, #155 and #156 into broader issues. The user corrected it twice: "you are confusing issues being indivisible problems vs. solving those issues which are done in batches", and "the issues are what divides. the batch is what merges multiple issues into one working session." The merges were undone.

**How to apply:** Never weigh the number of issues, and never argue that issues belong together because they land in one batch. When unsure whether a part is its own problem, file it apart. The batching itself is [[a-push-solves-every-open-issue-of-one-stack]].
